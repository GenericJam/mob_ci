# mob_ci revived: version rows, iOS lane, plugin self-tests, generated compatibility matrix

- Date: 2026-10-08
- Status: accepted
- Linear: MOB-410 (epic), MOB-411 … MOB-419

## Context

mob_ci stalled on 2026-06-23 at milestone 3, pinned to mob_dev 0.6.5. On
2026-10-08 the NUC's core checkouts were reset to origin/master (mob 0.9.14,
mob_dev 0.7.16, mob_new 0.6.7), and mob_ci compiled without a single undefined
function and ran `mix ci.device` on the live farm: static gate clean, a
ci-redroid booted, the harness with its five fixture plugins built and
deployed in about four minutes, P1 and P2 passed. The code is usable; the
design (`2026-06-19-mob-ci-design.md`) stands.

Since June the ecosystem grew to 26 plugins, every one of which has
ubuntu-only CI that never compiles its native code; MOB-372, MOB-373 and
MOB-376 were build-path bugs ("dev build works, release doesn't" and the
reverse) that no static check sees; and nothing records which versions of
mob, mob_dev, mob_new and each plugin work together. A separate plan written
on the Mac the same day (`mob_matrix`, one commit, now deleted) overlapped
with mob_ci on everything Android and added the items below. They are merged
here; mob_ci keeps its name, layers and invariant catalog.

## Decision

Keep mob_ci as the single orchestrator on the NUC and extend it on five
fronts. Each is a Linear sub-issue of MOB-410.

### 1. Plugin self-test contract (MOB-411, MOB-418)

P3 proves a NIF initialized through a safe probe from `device_caps.exs`, a
table mob_ci maintains about plugins it does not own. The contract moves
into the plugin: `mob` gains a behaviour

```elixir
@callback run(%{platform: :ios | :android, device: :simulator | :emulator | :physical}) ::
            :pass | {:fail, String.t()} | {:skip, :needs_hardware | :needs_user | String.t()}
```

declared in the manifest as `selftest: Module`, validated by mob_dev (warning
for one release, then an error). A self-test must get a real answer back from
native code. mob_ci runs every active plugin's self-test over dist (new
invariant **P12**) and compares with the plugin's singleton run: failing
alone is `plugin:<p>`, failing only in company is `conflict:<set>`.
`device_caps.exs` keeps only what the plugin cannot know (which fixture host
can build it). Pilots: mob_location, mob_whisper, mob_deliver; then the other
23, one PR each.

### 2. Version rows (MOB-413)

Every run resolves a version row and records the exact versions in each
result:

| row | mob, mob_dev, mob_new, plugins | meaning |
|---|---|---|
| `hex` | latest Hex of each | what a user gets today |
| `master` | origin/master of each repo | what ships next |
| `rc:<repo>@<sha>` | one repo at a sha, rest hex | before cutting a release |

Hosts are generated by `mix mob.new --blank` of the row's mob_new (so the
generator is under test every night), with `--local` for `master`, then
`mob.exs` written with the set, trusted keys and acknowledgements. The
existing `fixtures/_harness` stays for the fixture plugins.

### 3. Sets (MOB-413)

Besides the StreamData sweep (kept: shrinking to the minimal failing pair is
the best bug report), deterministic sets run every night: `blank`, the
mob_new `default`, every `singleton`, `all` (26), a committed pairwise
covering array (~12 hosts), and `demo` (mob_plugin_demo's 18). A failing
sweep seed is committed under `priv/sets/` as a regression set. Rationale:
build-time conflicts are near-monotonic, so `all` catches most pairs cheaply,
singletons catch a plugin that only works because another supplied its
framework or permission, and the array catches order-dependent merges.

### 4. iOS lane and release paths (MOB-415)

mob_ci is Android-only. iOS cannot leave the Mac mini, and the Mac has about
8 GB free, so it becomes a thin worker driven over ssh from the NUC, the way
`sloppy_joe_server` already drives `claude@mac.local` for the sim farm: one
host at a time, generate, build simulator + device + `mix mob.release --ios`,
run P2/P12/health on simulators and the iPhone (via `agent-lease`), return
results, delete the tree. Release paths (`mix mob.release --android` too) are
cells in their own right: that is where the recent bugs were. Refuse to start
a cell under 5 GB free.

### 5. Results store, reports, triggers (MOB-414, MOB-416, MOB-417)

Results move from per-run artifact dirs into SQLite on the NUC (run, cell,
versions, layer, outcome, duration, log path). Reports are generated from it:
`matrix.md` (latest grid per row) and `COMPATIBILITY.md` (version tuples
with passing `default` and `all` on every platform; the documentation links
to it as "verified combinations"). Muster `#mob` gets one post per run;
`@kevin` only when the `hex` row regresses. Triggers stay thin per
`2026-06-23-trigger-adapters.md`; added: a git-remote poller (any host,
no GitHub Actions) that runs the static gate on a new master sha and queues
`default` + the changed plugin's singleton + `all` on `master`, and an
optional pre-push enqueue from the Mac.

## Consequences

- mob_ci becomes the owner of "does the ecosystem work for a user", for both
  platforms and both version rows. Its nightly is the release gate's
  evidence; `rc:` rows replace hand-run checks before a bump.
- Plugins carry their own proof. mob_ci stops knowing plugin internals once
  P12 exists; `device_caps.exs` shrinks.
- The NUC checkouts of mob, mob_dev and mob_new are reset to origin/master
  and must stay there; mob_ci's `path:` deps point at them for `master`
  rows, and Hex deps for `hex` rows.
- Working on the NUC from the Mac: `ssh nuc` (alias in `~/.ssh/config`,
  key auth, BatchMode), `~/.bashrc` activates mise and the Android SDK for
  non-interactive commands. mob_ci needs a git remote so both machines can
  push; it had none.
- Open: whether redroid serves arm64 as well as x86_64 (mob_dev builds both
  ABIs); MOB-378 (stale SELinux label on redeploy to a rooted emulator) may
  bite the farm; the Mac's `claude` account must be able to sign with the
  Apple Distribution identity for the iOS release path.
