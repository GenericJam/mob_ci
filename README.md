# mob_ci

Orchestrator-first device CI for the mob ecosystem: generates host apps for
plugin sets at pinned versions, builds them, runs them on the redroid farm,
and checks the invariant catalog (P1–P11, P12 pending). Design:
`decisions/2026-06-19-mob-ci-design.md`; what the 2026-10 revival adds:
`decisions/2026-10-08-revived-version-rows-ios-selftests-matrix.md`.
Working conventions: `AGENTS.md`. Findings: `FINDINGS.md`.

```sh
mix ci.device --static                       # fixture harness, manifest gate only
mix ci.device                                # fixture harness, full P1–P11 on the farm
mix ci.device --host sloppy_joe              # the real app as host
mix ci.device --static --set all --versions hex
mix ci.device --set pairwise:3 --versions master
mix ci.sweep --static --set all --versions hex
mix ci.sets                                  # every named set
```

## Version rows and sets (`--set` × `--versions`)

A **cell** is a named set of plugins on a version row. Every cell run prints
the set and the exact versions it resolved, and every result carries them
(`MobCi.Result.set` / `.versions`, also in `artifacts/…/summary.json`).

### Rows — `--versions`

| row | mob, mob_dev, mob_new and every plugin in `priv/plugins.exs` |
|---|---|
| `hex` (default) | latest stable release on Hex, pinned `== x.y.z` |
| `master` | the GitHub default-branch sha of each repo, as a `path:` dep on a per-sha checkout |
| `rc:<repo>@<sha>` | `<repo>` at `<sha>`, everything else `hex` — the pre-release check |

`MobCi.Versions` resolves a row; clones live under `~/.cache/mob_ci/repos`,
per-sha worktrees under `~/.cache/mob_ci/src/<repo>/<sha>`, unpacked Hex
tarballs under `~/.cache/mob_ci/hex`. A bad value is an error naming the
accepted forms.

### Sets — `--set`

| name | what |
|---|---|
| `blank` | no plugins |
| `default` (default) | what `mix mob.new` activates, read from the row's mob_new |
| `singleton:<plugin>` | one plugin alone |
| `all` | every buildable first-party plugin |
| `demo` | mob_plugin_demo's activation (its first-party part), `priv/sets/demo.exs` |
| `pairwise:<i>` | row *i* of the committed pairwise covering array, `priv/sets/pairwise.exs` |
| `random:<seed>` | a replayable 3–8 plugin subset |
| `<file>` | `priv/sets/<file>.exs` — a committed regression set (a list of plugin atoms) |

`mix ci.sets` lists them; `mix ci.sets --regen` rewrites the covering array
after `priv/plugins.exs`, `priv/device_caps.exs` or `priv/sets/exclusions.exs`
changes the pool (the test suite fails until you do); `mix ci.sets --check`
verifies it. Plugins `priv/device_caps.exs` marks `buildable: false` are
excluded from every set.

**Exclusions.** `priv/sets/exclusions.exs` parks a plugin (`plugin: "F<n>:
reason"`) while a known finding breaks every host that activates it, so
`all`, the pairwise rows and the other built sets stay buildable. Its
`singleton:<p>` still runs, and `--static` plans every set with the parked
plugins included, so the collision stays on the report until the entry is
removed. Today: `mob_midi` (F9, plist key collision with `mob_bluetooth`).

### Hosts

A cell's host is generated by the row's own mob_new (`mix mob.new --blank`,
`--local` on `master`), its deps pinned from the row and its `mob.exs`
written with the set, the first-party trust key and acknowledgements for
unsigned path checkouts (`MobCi.Host`). Generation failures are layer
`mob_new`, `deps.get`/`compile` failures `elixir`. Hosts are reused under
`fixtures/_hosts/` (gitignored); `--fresh` regenerates. The fixture harness
(`fixtures/_harness`, `mix ci.device` with no `--set`) is unchanged.

Details and rationale: `decisions/2026-10-08-version-rows-and-deterministic-sets.md`.

## Tests

`mix test` (no device, no network; `:integration` excluded). The
version-row and set tests stub the network. To really generate and compile
a host for `default` on `hex`:

```sh
mix test test/mob_ci/host_test.exs --include integration --only integration
```

There is no GitHub Actions workflow in this repo: the orchestrator runs on
the NUC (`priv/ci-run.sh`, `priv/triggers.md`).
